# Regroup learning

Goal: teach recovery choices after a loss without forcing a tutorial or inventing income. IDEAL: identify opaque preparation paths; define truthful, useful choices; explore forced coaching versus optional help; act on repeatable contextual regroup help; look back through tests, Playwright and independent audit. 5 W's: new/returning players; preparation after a defeat; result dialog; real loss or Retreat; help players change one thing and continue exploring.

Bounded design extends the existing result flow. A native collapsed disclosure names one currently funded preparation option, describes persistent cards with random summons, and explains earlier unlocked chapters when available. Rename the loss button to Prepare next attempt because it returns to ready and buys nothing. Keep actual combat advice, rewards, ownership and retry authority unchanged. No new persistence or economy rules. The user authorized autonomous brainstorming, planning, implementation, tests, PR, review and merge; routine approval handoffs proceed within that scope.

1. Write failing tests for real Retreat/loss, affordability boundaries, evolution prerequisites, capped upgrades/draws, optional earlier chapters, mutation-free rendering and absence on wins.
2. Implement a pure presentation helper and connect the loss result. Reuse the established disclosure style and native keyboard semantics. Verify focused/full tests and production build, then commit.
3. Add bounded production Playwright cases at 320x568 and 390x844: actual start/Retreat, keyboard opening, complete paragraph pixels, no spending, Retry ready state. Preserve all existing gates and publish focused evidence. Create PR, independently audit, fix supported findings, merge only after predecessor PRs and combined checks pass. Verify deployment separately.

Retention and fun are design hypotheses; these checks prove specific flow behavior, not engagement uplift.
